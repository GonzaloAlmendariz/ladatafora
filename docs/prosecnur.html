Prosecnur

El ciclo de una encuesta, en un solo paquete.

Tres etapas: codificar el instrumento y la base en sincronía, producir entregables (codebook, SPSS, frecuencias, cruces) y armar un plan visual que sale igual a PowerPoint o a Word. Escrito mientras trabajaba con el equipo de ACNUR PPRA.

Qué hace

Cuatro bloques

01

Codificar por familias

Una familia agrupa columnas alrededor de una variable padre. El equipo edita una plantilla en Excel y el paquete aplica esas decisiones a la base y al instrumento a la vez — porque si solo cambias la base, las etiquetas después no calzan.

02

Entregables estándar

reporte_instrumento() y reporte_data() preparan la base una sola vez. De ahí salen codebook, SPSS (.sav + .sps), frecuencias, cruces y reporte por enumerador.

03

Plan visual reutilizable

Presets (p_presets), piezas gráficas (p_barras_*, p_pie, p_donut), layouts de slides y composición con diapo(). El mismo plan se exporta a PPT o a Word.

04

Validación & índices

Plan de consistencia editable en Excel (cargar_plan_excel, evaluar_consistencia) y un DSL para índices compuestos: indicador(), nivel(), indice().

# Guía 1 · Codificación — adaptar instrumento y base
library(prosecnur)
inst  <- leer_instrumento_xlsform("cuestionario.xlsx")
datos <- leer_datos("respuestas.xlsx", inst)

fam   <- leer_familias_clasificar("familias.xlsx")
plant <- construir_plantilla_desde_familias(datos, inst, fam)
datos <- ppra_adaptar_data(datos, plant)
inst  <- ppra_adaptar_instrumento(inst,  plant)

# Guía 2 · Entregables — una preparación, cinco salidas
rp_inst <- reporte_instrumento(inst)
rp_data <- reporte_data(datos, rp_inst)

reporte_codebook   (rp_data, rp_inst, "codebook.xlsx")
reporte_spss       (rp_data, rp_inst, "base.sav")
reporte_frecuencias(rp_data, rp_inst, "freq.xlsx")

# Guía 3 · PPT plan — mismo plan, dos salidas
presets <- p_presets(tema = "editorial")

diapo(p_slide_portada("Informe · ACNUR · PPRA")) |>
  diapo(p_slide_2_graficos(
    p_barras_apiladas(rp_data, preg = "p3"),
    p_pie(rp_data, preg = "p7"), presets = presets))

reporte_ppt_plan(plantilla = "plantilla_16_9.pptx")

Reglas de validación

Qué se verifica por defecto

El plan se edita en Excel y convive con reglas propias en R, versionables con el proyecto.

  • R·01 Tipo y codificación select_one · select_multiple · numeric · date — resuelve dummies y repeats hard
  • R·02 Rango numérico min / max del XLSForm + outliers por módulo (z-score e IQR configurables) hard
  • R·03 Obligatoriedad required = yes → no puede estar vacío; expr_not_empty() hard
  • R·04 Saltos · relevance respuesta solo si la condición se cumple; separa N/A válido de error hard
  • R·05 Constraint de XLSForm evalúa expresiones declaradas en el formulario, incluyendo repeats hard
  • R·06 Plan Excel editable cargar_plan_excel() · reglas nombradas, documentadas y versionables hard
  • R·07 Other y texto abierto coherencia "otro → texto" con predicados expr_other_implies_text soft
  • R·08 Consistencia entre preguntas expresiones R por fila; auditar_regla() · observaciones_regla() soft
  • R·09 Trazabilidad por enumerador reporte_enumeradores() — duración, geolocalización, patrones de error soft

Preguntas

Dudas frecuentes

¿Funciona con formularios que no vienen de KoBo?

Sí. Mientras el formulario siga el estándar XLSForm (columnas survey, choices, settings), leer_instrumento_xlsform() lo lee. Está probado con KoBoToolbox, ODK y la plataforma PPRA de ACNUR. Para SurveyMonkey hay adaptadores dedicados.

¿El plan de validación se edita en Excel o se escribe en R?

Las dos cosas. generar_plan_limpieza() arma un plan inicial en Excel a partir del XLSForm; lo abres, revisas y editas con el equipo; lo vuelves a cargar con cargar_plan_excel(). Encima del plan puedes sumar reglas ad-hoc en R.

¿Qué produce exactamente el paquete?

Seis salidas sobre la misma base: PPTX con reporte_ppt_plan(), Word con reporte_word_plan(), SPSS .sav + syntax .sps, libros Quarto, XLSX (codebook, frecuencias, cruces) y un tablero Shiny interactivo.

¿Cómo se definen indicadores e índices compuestos?

Con un DSL mínimo: indicador(), nivel(), indice(), subindice() y predicados ind_alguna, ind_todas, ind_es, ind_en, ind_ninguna. Se visualizan con funciones graficar_*_dimensiones.

¿Qué pasa con los datos sensibles?

Prosecnur corre 100 % en local. No envía datos fuera del entorno de R y los reportes se renderizan en tu máquina. Puedes decidir qué columnas exportar en cada reporte y qué variables sensibles omitir del tablero Shiny.

¿Cómo se integra con una plantilla PowerPoint corporativa?

Pasas tu .pptx como plantilla en reporte_ppt_plan() o armas la presentación a mano con diapo() y los layouts p_slide_*. El paquete incluye inst/plantillas/plantilla_16_9.pptx como referencia.
